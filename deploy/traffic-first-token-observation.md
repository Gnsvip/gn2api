# 真实流量首字观察与可选自动停止调度

“智商检测 → 首字观察”观察用户请求实际使用的上游账号。默认只观察；管理员打开“连续性能异常自动停止调度”并保存后，开始建立参考。命中后停止该账号调度，需手动恢复；不额外发题、不取消当前请求。TPS 与首字同时变差是性能异常证据，不能单独证明限流或模型降级。

## 判定规则

- 按账号、上游模型、推理档位、服务档位、实际出站 HTTP / WS、首字口径、上下文区间、缓存比例、输出量分组。
- 首字与之前一致：HTTP 使用 semantic / visible（个别线路可配置 first_event）；WS 及 WS→HTTP 默认使用 ws_semantic。WS→HTTP 也遵守单账号显式 first_event 例外，并单独分组。开始处理通知不属于 ws_semantic。输入 tokens 为上游总输入，已含缓存，不重复相加。
- 上下文分桶：≤32k、32–128k、128–230k、>230k；缓存比例分桶：<50%、50–90%、≥90%；输出分桶：32–127、128–511、512–2047、≥2048。
- 每组取开启后、最近 6 小时内的前 20 个完整有效样本作为参考。不是健康认证；开始时已经持续很慢的账号不会因此被识别为从正常转慢。
- 参考 P50 必须大于 0，参考首字 P95 不得超过 P50 的 3 倍，否则只观察。每次判定重新从有界观察窗口计算，旧样本淘汰后参考会随窗口移动。
- 最近 10 分钟连续 3 个同类有效样本都满足：首字 ≥ max(5 秒, 参考 P50 × 3, 参考 P95)，全程 TPS ≤ 参考 TPS 中位数的一半，输出量在参考输出中位数的 0.5–2 倍内。异常需持续至少 30 秒，避免单次并发突发触发。
- TPS = output_tokens / 完整请求秒数，包含等待，可能包含推理 tokens；不是独立的正文解码速度。因此只用作辅助条件，不把两个相关指标说成两份独立证据。
- 单次异常、少样本、短输出、模型/档位/传输等不同组不会混合触发。失败、重试、取消、中断、媒体输出、不明口径等不纳入参考，并中断该账号已有连续异常计数。已在配置生效或冷却结束之前开始的请求，不用于新一轮学习。

## 停调度行为

满足条件的请求完整结束后持久写入 `schedulable=false`；没有定时恢复，不取消已经进行中的请求。并发完成使用数据库条件更新，只触发一次；账号已删除、手动停止、已有其他冷却、策略被关闭或修改时不覆盖。停止调度、最近数值证据与 scheduler outbox 同一 SQL 原子提交，立即同步调度快照，并用短期内存屏障覆盖传播间隙。内存屏障过期后数据库停调度状态仍生效。

原生 WS 下一轮读取最新账号可调度状态。账号已停止调度时，在发送上游前终止本连接并提示重连，由新的调度选择可用账号；不声称可以无缝转移仅存在旧上游连接内的上下文。当前已在执行的回答不中断。

停止调度后只能由管理员手动恢复。关闭保护开关、经过旧冷却时长或服务重启均不会恢复账号。手动恢复后从触发时间之后重新积累参考，排除触发前已开始的在途请求；恢复调度不等于已验证能力恢复。升级前已存在的临时冷却按原状态处理，不追溯转换成永久停止。

## 保存边界与接口

观察数据最多保留 24 小时、全进程 100,000 条有界数值/分组元数据，不保存问答正文、工具参数、凭据或请求头。重启清空，不回填历史数据库。每组保护计算最多保留 20 个参考和 3 个近期样本，最多处理 128 组；页面保护区展示前 20 组并提示余量。

账号 Extra 键 openai_traffic_guard_v1 保存开关、策略版本和开始时间；旧 cooldown_minutes 字段仅保留兼容，不再控制新触发的恢复。旧的 openai_traffic_protection 残留永不生效。openai_traffic_guard_last 仅覆盖保存最近一次触发的参考数值和 3 个异常数值，不追加历史文件或正文。停止调度证据使用触发时间且 until_unix 为 0，不写临时冷却字段。

- GET /api/v1/admin/accounts/:id/traffic-observation?window_minutes=60：1、6、24 小时统计、TPS 中位数、保护配置、学习进度、最近触发证据。
- PUT /api/v1/admin/accounts/:id/traffic-guard：{"enabled":true}。相同开关重复保存不重置学习；更改开关会重新开始。兼容旧客户端提交合法 cooldown_minutes，但不按它恢复账号。
- GET 保护视图包含 action=stop_scheduling、paused 状态及最近触发证据。扩展仅在后端明确支持该动作时开放新开关。

两个接口沿用管理员认证；受限管理 Key 默认不开放这两个端点。当前部署为 systemd 单进程；多进程的观察窗口不共享，不宣称跨实例统一学习。数据库停止调度状态共享并以原子条件更新防重复。

## 本地验证和上线

验证规则边界、分组隔离、失败/少样本/短输出、配置关闭、并发触发、数据库失败、持久状态与旧配置、WS 下一轮、管理员权限及浏览器保存/失败提示/窄屏布局。使用模拟 SSE/WS，不产生模型探测费用。

需要后端二进制与 ModelTrace 扩展一起更新。实现不自动启用线上账号；待用户要求发布后仅构建 Linux amd64，先发布 GitHub，再按部署授权更新服务器。
