# 真实流量首字观察（v0.2.59）

本阶段只观察，不自动停止调度、不设置冷却、不取消请求、不调用模型探针，也不按首字推断模型身份。此前未发布的单次超时保护及其配置接口已撤去；即使账号 Extra 中残留 `openai_traffic_protection`，也不生效。既有独立的限流、错误恢复与主动归因策略不由本功能修改。

参考 ranxi2001/sub2api production `e14887303651dd023e956339c5aa00637b4a87e5` 的有效请求过滤与窗口统计思路。参考实现仍需手填阈值，不带自动学习、最低样本或连续异常门槛，本版不照搬其自动暂停动作。WS semantic 判断另按 v2.19.4 补齐，包括推理结构识别、空 delta 过滤及各链路独立计时；缓冲、重试与调度不使用这个计时判定。

## 数据与口径

- 新进程启动后只收集新请求，不回填旧数据库或选择性慢请求日志。普通 HTTP 流开始时固定其 `semantic` / `visible` 口径；WS 入口或出口（含 WS→HTTP）使用 `ws_semantic`，收到明确类型的推理条目/片段或非空内容即记时。开始处理通知、空或非字符串 delta 不计时。推理信号不等于正文到达。
- 按实际承接请求的账号、发送模型、有效推理档位、服务档位、实际出站 HTTP / WS、计时口径、上下文区间分组。输入 token 按上游总输入计，已包含缓存 token，不再重复相加。区间为 ≤32k、32–128k、128–230k、>230k；它们不是停用阈值。
- 必须有匹配账号、单次尝试、HTTP 200（HTTP 路径）、完整成功终态、无传输失败/客户端取消、合法首字、至少 2 个输出 token。媒体生成、非流式、重试、失败、缺少证据或首字等单独计数，不进入成功分布。
- 已覆盖 Responses HTTP/SSE（含透传及转换）、HTTP→WS、原生 WS 连接池/透明转发、WS→HTTP。透明 WS 在每轮终态写出后收集该轮记录，不用 Gin 的首轮记录；不会重复计入回调。
- 原生 Chat Completions 等尚无完整 Responses 耗时证据的兼容路径列为 `missing_trace`，不凭部分计费用量冒充成功样本。专用音视频、图片、嵌入、搜索端点不属于本观察范围。被排除的计数是已观察到的转发尝试，不是全站错误率。
- 窗口支持 1、6、24 小时，显示有效样本数、均值、最近秩 P50/P95、前后半窗口的 P50 与各自样本数。无样本返回 null / 空列表，不是 0。最多展示样本最多的 50 组，额外组数明确提示。

## 保存边界

全进程有界内存环形缓冲，最多 100,000 条数值与分组元数据；按时间保留最近 24 小时，访问或新流量时淘汰过期项。无请求/回答正文、工具参数、凭据、请求头或逐条请求 ID，无新增数据库表、正文文件、采样日志及后台探针。

缓冲的固定结构约 14.5 MiB，另有长度受限的模型/档位字符串；上限与账号数无关。达到容量会覆盖最早样本；页面提示窗口不完整。重启即清空，页面显示采集起点。多进程不共享数据，当前 systemd 单进程部署适用。删除的账号不能通过此接口读取，已有内存片段按窗口/容量淘汰或重启清空。

管理员只读 API：`GET /api/v1/admin/accounts/:id/traffic-observation?window_minutes=60`。没有写配置或停用接口，沿用管理员认证；受限管理 Key 未开放该新端点。扩展“智商检测 → 首字观察”查看统计，不需要保存或填写阈值。

## 上线与验收

这项需要后端二进制与扩展一起更新，单独替换扩展不会开始采集。先完成 GitHub 发布，再经用户部署确认更新 Linux amd64 二进制与扩展；上线时旧 `first_event` 配置按本次代码归一为 HTTP `semantic`，历史用量不重算。

部署后检查服务版本、只读 API、采集起点和真实 HTTP/WS 各组样本增长；至少观察一个完整窗口，通常先看 24 小时。必须结合每组样本数、档位、上下文与失败情况再讨论阈值；本版不会自动生成或启用停调度规则。

本地验收使用模拟 SSE/WS 上游，无真实模型调用。包括慢请求不被观察功能中断、无调度写入、完整性过滤、账号隔离、窗口/容量淘汰、并发读写、原生 WS 多轮、双向桥接、管理员权限、桌面/窄屏及只读页面请求。
