# GN2API v0.2.55

修复 WS 临时连接失败后，持续使用的会话长期停留在 HTTP 的问题。恢复时使用完整历史建立新 WS，再继续工具增量续传；同时修正 OAuth 模型目录的上下文回退值及压缩参数同步。

- 临时故障首次冷却 30 秒，连续恢复失败逐步延长，最多 5 分钟。HTTP 请求不延长冷却时间，同一隔离会话只允许一个恢复请求；明确不支持 WS 的能力信号保持原处理。
- 恢复请求必须具备可独立发送的历史，不使用旧连接的增量锚点或缓存 turn-state。上下文池、原生 WS 透传及 HTTP→WS 路径覆盖恢复与工具续传；已输出的响应不自动重放。
- HTTP→WS 获取连接与普通重试共用总预算，避免第一次握手就超出总重试预算；正常推理和生成不受该连接预算截断。
- OAuth Astra 缺少已同步窗口时，采用采样确认的 Codex 默认/最大窗口 272000 / 872000，避免套用公共 API 的 1050000。账号明确同步的窗口仍优先，API Key 默认保持原行为。
- 同步并保留上游明确返回的自动压缩阈值和有效窗口比例；实时清单的 null 不被旧阈值覆盖。不统一强制提前压缩，不改模型、推理等级或 `visible` 首字口径，前端源码未改。

验证：2,526 项测试及子用例通过，0 失败；1 项独立数据库集成测试因未配置专用测试库跳过。包含本地 HTTP 回退→新 WS 完整历史→工具增量、原生 WS 两种模式续传、并发恢复、连接预算及目录同步测试。未把本地受控上游测试描述成生产性能验收，也不承诺所有首字低于 10 秒。

仅发布 Linux amd64 二进制包，内嵌前端，附构建信息及 SHA256 校验文件。详细行为和验证范围见 [HTTP/WS 增量与恢复说明](HTTP_WS_INCREMENTAL.md)。
