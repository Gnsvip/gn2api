# GN2API v0.2.63

修复账号已停止调度、旧 WS 长连接却继续发起新一轮的问题，同时补齐单账号首次响应计时在 WS→HTTP 链路的遗漏。

- 原生 WS 后续轮次读取账号最新可调度状态，覆盖 WS 上游和 HTTP 桥接。手动停调度、冷却或删除后，下一轮在发送上游前要求客户端重连重新选号。已经开始的回答正常完成；不承诺自动转移仅保存在旧上游连接中的上下文。
- 显式配置 `extra.openai_http_ttft_mode = "first_event"` 的 OpenAI API Key 账号，在 WS→HTTP 链路也按首个有效、非终止 Responses 事件记时。#12140 已有配置可直接生效；未配置的账号、实际 WS 上游和全局口径不变。首正文和首内容仍分别记录，计时不改变缓冲、超时或失败切换，不修改历史用量。
- “智商检测 → 首字观察”增加可选的连续性能异常冷却，默认关闭。按同账号、模型、档位、传输、口径、上下文、缓存比例和输出量学习参考；20 个参考样本后，至少连续 3 次首字明显升高且全程 TPS 降至参考的一半、异常持续至少 30 秒，才触发默认 10 分钟冷却。
- 页面显示全程 TPS、学习进度及最近一次触发的数值证据。样本不足、短输出、失败和取消不会触发自动冷却；参考不稳定时只观察。TPS 包含等待时间，该保护不能证明模型降级。冷却后重新学习，恢复调度不代表已验证能力恢复。
- 冷却条件更新和调度通知原子提交，不覆盖手动停用或其他冷却，并发异常只写一次。仅覆盖保存最近一次数值证据，不记录问答正文，不额外调用模型。

本地验证覆盖首字例外与普通账号隔离、HTTP 桥接失败恢复、原生 WS/WS→HTTP 手动停止后的下一轮、完整回答保留、连续异常规则、并发触发、管理员接口及浏览器保存和窄屏布局。测试使用受控上游，不消耗真实模型 token；上线后的真实请求效果需继续核对。

只提供 Linux amd64 二进制，包含同源构建的前端及 `extensions/modeltrace/modeltrace.js`，附 SHA-256 校验和构建记录。不构建其他平台或容器镜像。主程序与扩展页面需一起更新，独立 ModelTrace Python 服务无需更新。

详细规则见[首字观察与性能冷却](../deploy/traffic-first-token-observation.md)和[计时定义](../deploy/request-timing-evidence.md)。
