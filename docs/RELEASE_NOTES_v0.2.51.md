# GN2API v0.2.51

修复 systemd 停止或重启网关时，运行中的数据库备份被提前终止的问题，并让定时备份在导出开始前即可被运维检查发现。

## 变更

- systemd 模板和安装脚本采用 `KillMode=mixed`：先只向网关主进程发送停止信号，由网关等待备份/恢复结束；超过总停机期限时仍清理整个进程组。
- 备份操作统一使用 30 分钟时间预算。停机等待预算调整为 32 分钟，包含对象清理时间；systemd 的总停止期限为 33 分钟。没有活跃操作时立即结束，不固定等待上述时长。
- 定时备份在启动 `pg_dump` 前持久保存 `running/dumping` 状态，上传时显示 `uploading`，完成或失败后清除进度标记。无法保存初始记录时不启动导出；取消后的失败状态使用独立上下文保存。
- 计划部署应在网关仍提供服务时等待运行中的备份/恢复完成，再进行重启，避免把备份耗时变成停机时间。

## 验证

- 63 个备份相关顶层测试通过，含子用例共 70 项。覆盖备份、恢复、分卷、保留策略、提前保存运行状态、取消后终态保存、正常停机等待和超时取消回收。
- 隔离 systemd 服务实测：`control-group` 向子进程发送 SIGTERM，子进程被终止；`mixed` 让主进程等待子进程正常结束。未用生产备份制造中断。
- 安装脚本语法检查通过。v0.2.50 的长历史自动增量和 visible 首字统计保持不变。

## 已有 systemd 安装

替换二进制不会自动更新已有服务配置。需要在服务或 drop-in 中设置 `KillMode=mixed`、`TimeoutStopSec=33min`，执行 `systemctl daemon-reload`，确认没有运行中的备份/恢复后再重启。部署方法见 [部署说明](../deploy/README.md)。

仅提供 Linux amd64 二进制包，内嵌同一提交构建的前端，并附构建信息和 SHA256 校验文件。
