# GN2API v0.2.52

修复复用的上游 WebSocket 连接接近 60 分钟寿命上限时，仍接收新一轮请求、随后在回答中途被上游关闭的问题。

## 变更

- HTTP 转 WS 在借出连接后、写入请求前检查剩余寿命，也覆盖排队期间连接变老的情况。原生 WS 在两轮之间检查长期持有的连接。
- 默认为下一轮预留 15 分钟处理时间和 1 分钟余量；配置的读取等待时间或显式请求剩余预算更长时，会提前轮换。不会用轮换定时器中断正在执行的回答。
- 新连接上的 `store=false` 续传仅在完整历史可验证时重建，保留模型、推理等级、指令、工具定义、助手回答、推理项和工具调用关系；未知或不完整历史不会被静默当作完整上下文。
- 恢复输出按原始序号校验，兼容终态省略部分输出、并行输出完成顺序不同的情况。换连接后建立新的续传基准，后续继续增量发送。
- 原生 WS 在尚未向客户端输出时遇到连接到期错误，可安全恢复一次；已经输出后不重放整轮，避免重复回答和重复执行工具。
- 仅增加连接轮换元数据日志，不新增请求正文落盘。保留 `visible` 首字统计、大请求 HTTP 预检兜底及 v0.2.51 的备份保护。

## 验证

- `unit` 模式 399 个相关顶层测试通过，含子用例共 849 项。
- 覆盖连接老化、排队、严格连接绑定、HTTP/原生 WS 换连接后恢复增量、图片和工具历史保留、输出前重试、输出后不重放、不完整历史及乱序输出。
- Linux amd64 编译通过。到期场景使用本地受控连接年龄复现，未对生产连接注入故障。

OpenAI 的 60 分钟连接寿命限制仍然存在。没有明确总时限且单轮持续超过预留窗口的请求仍可能触及该限制；本版本不会为轮换而强制截断长回答。

仅提供 Linux amd64 二进制包，内嵌同一提交构建的前端，并附构建信息和 SHA256 校验文件。
