# GN2API v0.2.67

修复官方 Codex 在站内余额不足时反复重连的问题。Codex Responses 流式请求使用可终止本轮的 `response.failed + insufficient_quota`，普通请求继续返回 HTTP **403**。

- HTTP/SSE 使用 200 传输失败事件；WS 在本地握手后发送失败事件并关闭。后台按站内余额拒绝记录逻辑 403，另存实际传输状态，不记为成功推理或上游限流。
- 覆盖鉴权时余额不足、排队/预留后余额不足，以及已连接 WS 下一轮余额不足。拒绝发生在本轮调用上游之前。
- 有余额时沿用原有上游转发、真正 429 的重试、401 后切号和上下文续传。余额恢复后可再次正常请求，不新增用户冷却。
- 不改变首字计时、#12140 的独立计时规则、前端、数据库结构和余额结算方式。

## 验证

- 余额准入、计费、预留、监控归因、HTTP/WS 换号和上下文续传相关回归通过。
- 官方正式 Linux Codex 0.166.0 配合实际鉴权中间件及错误构造器验收通过：HTTP 每轮一次；WS 无 HTTP 回退和重连提示。
- 长驻 app-server 使用官方 VSCode 宿主标识，主动发送两轮，各收到一次终止额度错误；保持客户端运行 60 秒，未出现后台重试。
- WS passthrough、ctx_pool 和 http_bridge 均验证：有余额首轮正常执行，结算后余额不足，下一轮失败且不再调用上游或扣费。
- 第三方封装客户端仍需线上观察；外层程序自行重新提交任务不属于 Codex 单轮自动重连。

仅发布 Linux amd64 二进制，内嵌同一提交构建的前端，附 SHA256 校验和构建信息。详见[余额拒绝处理说明](../deploy/balance-denial-repair.md)。
