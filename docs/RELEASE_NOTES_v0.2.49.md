# GN2API v0.2.49

修复部分官方 Codex 请求在工具续传时被网关改写调用编号，导致相同历史无法命中自动增量的问题。保留 `visible` 首字口径，并为 HTTP → WS 转发增加简短的耗时分段诊断。

## 变更

- 统一原生请求识别：官方客户端使用顶层 `instructions` 或未标注 base-instructions 的 developer 消息时，合成器、输入过滤器、HTTP/WS 兼容路径按同一原生历史规则处理。
- 工具调用的 `call_id` 原样保留，不再把 `call_…` 改成 `fc_…` / `ctc_…` 后触发历史不一致。修复同类请求重复补默认提示及剥离原生工具元数据的问题。
- 原生识别覆盖 HTTP、透传、HTTP → WS、HTTP 回退，以及原生 WS passthrough / ctx_pool 的首轮和后续帧。账号默认能力或强制出口身份本身不被当成原生输入证据。
- 继续过滤无效消息 ID。旧式官方请求中类型错误的工具条目 `id` 仍被过滤，合法原生 `ctco_` 输出 ID 及 `call_id` 配对保留。真实调用编号、参数、上下文或未知字段发生变化时，仍禁止误用自动增量。
- 在已有访问日志中增加最后一次 WS 尝试的连接获取、排队、写入、首个事件及首个可见内容等数字字段。重试或切换账号清除旧值，不保存正文、工具参数、图片或密文。

## 首字口径与限制

- 沿用 `visible`；通知、空占位及仅终止事件不会充当回答首字。无独立内容事件时首字仍可为空，不用总耗时补值。
- 新增分段诊断目前覆盖 HTTP → WS 路径。首个事件可能是通知，不能等同于首个可见内容；发送后的等待也不能全部归为模型计算。
- 本次修复消除已复现的误发全量机制，不保证所有请求命中增量或固定首字速度。历史未保留原文的请求不能逐条确认根因。

## 验证

- 505 个相关后端顶层测试通过。
- 修改前，顶层 instructions / developer 两种提示形式 × function / custom 两种工具类型均复现调用编号差异；修改后四组各连续三轮，8 次续传全部命中增量，只发送新工具结果，保留模型和 xhigh。
- HTTP、回退和原生 WS 两种模式的工具 ID、元数据、无效 ID 防护及首字回归通过。
- 本机原生 Codex app-server 的受控回放中，7 种工具编号均原样回传，客户端配置未修改。

以上是受控上游与回归验证；线上效果仍需部署后核对。续传及诊断字段说明见 [HTTP/WS 自动增量说明](HTTP_WS_INCREMENTAL.md)。

## 发布产物

仅提供 Linux amd64 二进制包，内嵌从本次提交构建的前端，并附构建信息和 SHA256 校验文件。不构建容器或其他平台。
