# GN2API v0.2.71

修复运行中请求遇到正常部署重启后，费用预留未及时释放、导致仍有余额的用户收到“余额不足”的问题。

- 退出时统一跟踪 HTTP 与原生 WebSocket handler，包括 HTTP Server 默认不等待的已升级连接。先停止接收新请求并等待 30 秒；仍未完成的请求会取消并关闭连接，再等待最多 15 秒完成 handler 清理。
- 请求退出后先排空用量计费任务，再关闭计费缓存和 Redis。继续保留异步计费完成前的预留，不批量清除其他正在运行的请求。
- 区分真正余额不足与其他请求暂时占用余额。临时占用返回 `409 balance_temporarily_reserved` 和 `Retry-After: 2`，不会被包装成欠费终止事件。真正余额不足维持普通 HTTP 403、Codex 流式失败通知。
- 并发防透支、原有余额原子复核、首字计时及模型转发规则保持原有语义。

验证包括生产案例金额回放、HTTP/WS 取消后的异步结算、其他活动请求预留保留，以及 Linux 两个连续进程的 SIGTERM 重启验收。强制 SIGKILL、机器掉电等无法执行清理的情况仍由已有 Redis 预留 TTL 兜底；不宣称正常退出修复能够执行崩溃进程的清理。

仅发布 Linux amd64 二进制，无需更新前端或 Nginx 防护配置。
