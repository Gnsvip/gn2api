# Sub2API 0.2.20.4

修复网关重启或 WS 连接替换后，完整历史超过单条消息保护阈值而反复回退 HTTP、无法重新建立增量的问题。

- HTTP→OAuth WS 在历史完整且可安全分段时，先用 `generate:false` 分段恢复上下文，再生成当前回答。成功后继续严格校验完整历史，后续工具结果可重新使用增量。
- 保留图片、摘要、模型、推理等级和工具调用关系；工具调用与结果不跨分段，不复用旧连接的响应锚点。单条或完整工具组超限时保留完整 HTTP 兜底。
- 内部预热不触发回答首字。预热报告的实际输入用量独立预留和结算；后续失败也不会漏记已报告用量。恢复有大小、段数、超时及取消边界，凭证和上下文错误沿用既有处理。
- 保留默认 15 MiB 单消息保护阈值；它是基于此前 OAuth 出口实测的安全余量，不是官方公开规定的统一上限。

验证：217 项相关测试及子用例通过。隔离进程运行实际 Forward 代码连接真实 OAuth 上游：16,792,050 字节合成图片请求分两段成功走 WS，后两轮成功增量续传。此验收不等于所有生产客户端和原生 WS 入口均支持大包分段恢复，也不保证首字小于 10 秒。

本版未修改前端和既有首字规则。仅提供 Linux amd64 二进制；运行包不含测试、夹具或验证脚本。
