# GN2API v0.2.57

修复 OpenAI OAuth 凭据已被永久拒绝时，请求在获取访问令牌阶段直接返回通用 502、未进入账号切换流程的问题。现在这类错误进入现有调度重试流程，在分组、模型与重试次数等限制内选择下一个可用账号或 API Key；确认永久失效的 OAuth 凭据停止调度，等待重新授权。

- HTTP 直通与 WS 握手收到 401 时，在已有的有界凭据重读、刷新恢复仍未成功后，允许切换下一个候选。覆盖 HTTP/SSE、HTTP → WS、原生 WS 连接池和 WS 直通入口。
- 停调度操作使用完整凭据条件更新，并与调度失效通知原子写入，避免旧请求迟到的错误停用管理员刚重新授权的账号。内存中的失效标记也仅匹配被拒绝的凭据版本。
- 临时刷新错误不会被本次逻辑判定为永久失效。仅因本地已知 OAuth 凭据失效而耗尽候选时，返回明确的 OpenAI 账号不可用提示；不再误用其他平台的错误文案。
- 换号重试遵守既有的响应写出及上下文恢复限制。WS 后续轮次重建连接时若认证失败且无法安全重放，由客户端重新连接并恢复完整上下文，绝不把会话首轮当成本轮重放。

不修改模型、推理档位、上下文和工具关系，不改变 `visible` 首字统计。前端源码未改动，发布包重新构建并内嵌前端。新增失效状态仅保留凭据摘要与固定原因，不新增真实请求、回答或密钥正文记录。

凭据被上游撤销的原因仍需单独调查；本次修复自动切换与失效账号隔离，不能恢复已撤销的授权，也不代表所有流式断连问题均已解决。

验证：7 个包内 5,187 项测试及子用例通过，0 失败；6 项既有用例跳过，其中 5 项需要专用数据库，1 项为已有占位用例。受控本地 HTTP/WS 上游验证了失效 OAuth 切换健康 OAuth 或 API Key、真实 WS 握手 401 后切换、候选耗尽、临时刷新失败、并发重新授权保护及后续轮次防误重放。数据库条件更新使用受控 SQL 执行器测试，未进行真实数据库并发集成验收；这些结果不等同于生产流量验收。详细验证结果随构建信息发布。

仅发布 Linux amd64 二进制包、构建信息及 SHA256 校验文件；本次发布不自动部署服务器。
