# GN2API v0.2.64

## 工具内容及时转发与传输开销

- 自定义工具转换为 function 工具的 HTTP 上游返回增量时，网关现在逐步恢复工具输入，第一段内容不再等待完整参数结束。适用于 HTTP 客户端和 WS 客户端连接 HTTP 上游。
- 第一段立即发送，后续仅合并缓冲区内已经收到的同一工具调用片段，最多 16 KiB 原始参数。读取下一批上游数据前刷出，不增加等待计时器。
- 减少重复 JSON 编码及相同完成参数的重复解析；保留调用关系、完整结果、Unicode 转义和前缀一致性校验。格式错误、断流和失败终态不会伪造成功或重放已发送内容。
- 增加工具转换前后的首内容时间诊断，仅保存时间与事件类型，不记录工具参数正文。
- 保留 WS 账号失效后的完整上下文切号流程。HTTP 上游仍走 HTTP；单账号 `first_event` 计时和其他线路的首字规则保持不变。

五轮交替本地 TCP 测试中，1 MiB 工具输出整段中位耗时：HTTP→HTTP 为 309.762→283.587 ms，WS→HTTP 为 361.945→351.262 ms。此前未发布候选的 465/574 ms 回退已改善。固定节奏持续输出总耗时变化约 0.09%～1.12%；其他突发场景仍有最高约 5% 的波动，未声明所有线路均提速。这些结果不代表生产公网或真实模型生成速度。

## 余额不足错误与监控

- Responses 在准入时余额耗尽，HTTP 和 WS 握手统一返回 429 `insufficient_quota`；已连接 WS 返回终止额度错误，已提交 SSE 心跳的请求发送 `response.failed`，避免只显示断流。
- 补齐余额/额度错误在 Ops 及监控聚合中的识别。余额门槛、在途预留及结算逻辑保持不变。
- 提供有完整来源校验、只读预览和幂等保护的历史分类修复工具，升级不会自动重写历史统计。见[操作说明](../deploy/balance-denial-repair.md)。

## 独立 ModelTrace 扩展

- 自定义问答启用自动停止后，当前完整轮次出现一个红点即可停止调度，包括当前轮人工标红；历史旧记录、请求错误及不完整轮次不追溯触发。数字归因保留原连续次数规则。
- 糖果题恢复完整原文和数量表，预期答案保留 21。仅迁移未编辑的旧默认题；保留自定义题和历史记录。
- 保留自动停止开关当前状态，不替管理员开启。升级脚本会备份并验证既有数据，等待正在执行的检测轮次结束。

## 验证与安装

- 工具/计时/流式相关 1066 个顶层后端测试通过；160 个本地传输场景完成内容一致性检查。
- 余额相关 handler/middleware 1147 个顶层测试通过；官方本机 Codex 隔离测试确认额度错误终止、不回退重试。未调用真实模型。
- ModelTrace 288 项 Python 测试及浏览器界面检查通过。
- 仅构建 Linux amd64 二进制，包含新构建的嵌入式前端、独立扩展完整源码及 SHA256 校验文件；未构建其他平台或容器镜像。
- 扩展升级从发布包 `extensions/modeltrace` 目录执行 `upgrade_prompt_test.py` 预检，再用预检的服务哈希执行 `--apply --expected-service-sha256 ...`。需更新主程序与扩展以获得本版全部修复。
