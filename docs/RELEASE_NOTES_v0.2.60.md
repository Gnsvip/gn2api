# GN2API v0.2.60

修复余额检查与在途预留之间的并发窗口：请求即使提前通过余额检查，登记预留时仍会原子核对当前余额，不能在其他请求扣完余额后继续沿用旧检查结果获准。

- **原子余额准入**：当前余额、最低门槛、其他在途预留与本次登记在同一 Redis 操作内校验。同一用户的多个 Key 共用余额保护；固定金额费用仍要求余额覆盖全额。
- **缓存故障明确拒绝**：启用余额预留时，缓存能力缺失、读取或预留失败返回计费服务不可用，不再直接放行。显式关闭预留时保留数据库读取兜底。
- **防止旧余额回写**：冷缓存同步加载并检测并发修改；旧数据库快照不能覆盖后续扣费或失效。结算结果乱序到达不会抬高缓存余额，缓存已包含本笔扣费时也不会重复扣减。
- **结算与释放衔接**：缓存结算失败先失效缓存，失败恢复与释放预留保持关联，不再释放后异步重试减款。HTTP、WS 计费任务均携带原预留句柄。

保留已准入单笔请求允许超额结算的规则，因此不保证余额永不为负。此次修复针对旧资格检查被重复利用的竞态，以及余额缓存故障和更新交错；未改变估算上限、预留 TTL、无法估价时的配置或订阅/API Key 配额策略。

## 验证

- 550 项相关顶层后端测试通过，共 1125 个通过项（含子场景），无失败或跳过。
- 20 个提前通过余额检查的请求交错执行：仅首笔获准，扣费后其余 19 笔拒绝。
- 两个服务实例下，100 个请求同时争抢低余额：1 笔获准、99 笔拒绝。
- 覆盖缓存故障与恢复、冷加载与结算交错、固定费用、异步计费持有预留，以及 WS 透传/连接池/HTTP 桥接。
- 本机官方 Codex CLI 独立 loopback 验证：余额不足明确终止，1 次正式 WS 请求、1 次启动预热、0 次 HTTP 回退，无盲目重连。

上述测试使用本地服务、生产 Lua 的 miniredis 执行及本机客户端，不消耗真实模型 token；未进行生产负载验收或 Go race 检查。

仅构建 **Linux amd64 二进制**，内含重新构建的前端。另附同源 ModelTrace 扩展包、SHA-256 校验文件和构建记录；本次扩展源码无功能变更。不构建额外平台或容器镜像，不自动部署服务器。
