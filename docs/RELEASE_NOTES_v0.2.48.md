# GN2API v0.2.48

修复官方客户端回放工具调用时省略附加元数据，导致网关把相同历史误判为不同、重复发送完整历史的问题。OpenAI 首字统计默认改为 `visible`，排除额度通知。

## 变更

- 为上一轮上游输出的 function/custom tool 调用保留原始摘要及 Codex 原生回放摘要，兼容客户端省略 `cell_id`、`executed_tool_calls`、`tool_calls_complete`。替代摘要仅用于上游输出；已发送的历史输入继续严格比较，下一检查点以实际输入重新计算。
- 工具名称、真实参数、调用 ID、上下文、密文及未知字段变化仍阻止自动增量。兼容比较不改写实际请求或客户端收到的响应。
- 首字默认采用 `visible`：等待实际可见内容或工具输出，`codex.rate_limits` 在所有模式下均不计入首字。没有独立可观测输出时仍保留空值，不用总耗时补齐。
- 增量未命中的诊断仅记录固定字段名称。每个检查点最多保留 64 项输出的字段摘要，沿用 10 分钟过期；不增加问答正文、工具参数、图片或密文的持久化记录。

## 升级说明

- 已明确设置为 `semantic` 的实例保留原设置。如需采用新口径，请在管理设置中选择 `visible`；本版本不会追溯修改历史首字数据。
- 增量仍要求连接有效、作用域及参数一致、历史匹配、工具结果完整。真实历史变化等情况继续全量发送，不能承诺所有请求都命中增量。

## 验证

- 230 个后端顶层测试、47 个前端测试及前端类型检查通过。
- 官方 Codex 0.166 app-server 受控回放确认了工具附加元数据省略行为。
- 隔离网关连接真实上游，使用 gpt-6.1-sol / medium 与测试图片：首轮出站 74,158 字节；两次工具续传均在同一 WS 连接成功命中增量，各发送 2,248 字节，未重复发送历史图片。
- 同次试验的 `visible` 首字为 2.848、2.474、1.355 秒。这些是样本测量值，不构成速度保证。
- 历史 426 次前缀不一致缺少逐字段证据，不能认定全部由本次缺陷造成。部署后需依据新增诊断核对剩余未命中。

续传规则见 [HTTP/WS 自动增量说明](HTTP_WS_INCREMENTAL.md)。

## 发布产物

仅提供 Linux amd64 二进制包，内嵌从本次提交重新构建的前端，并附构建信息和 SHA256 校验文件。不构建容器或其他平台。
