# GN2API v0.2.50

修复长会话超过 2,048 条历史后无法建立自动增量检查点、工具续传重复发送完整历史的问题。完整历史检查点容量提升至 32,768 项，同时限制逐条指纹数组大小，保留全部历史的一致性校验。

## 变更

- 将完整输入加输出的检查点上限从 2,048 项提升至 32,768 项，与单轮最多 2,048 项输出的保护限制分开。
- 全部历史继续参与滚动 SHA-256 前缀校验，只保留末尾最多 2,048 项逐条指纹，切片容量也受限。在 Linux amd64 上该数组最多 176 KiB；不包括工具关联、字段摘要及处理请求的临时内存。
- 指纹尾部覆盖上一轮完整输出，继续支持已验证的原生工具元数据回放差异。较早历史的正文、图片、密文或工具结果发生变化时，仍回退全量；较早差异不保证能定位到具体字段。
- 超过容量限制时完整转发，不截断上下文。连接检查点有效期仍为 10 分钟，不因这项机制持久保存问答正文、图片、工具参数或密文。
- 保留 `visible` 首字统计、现有连接调度和断连处理。本次未给下游已取消的请求增加自动重试。

## 验证

- 576 个相关后端顶层测试通过，包含子用例共 1,157 项，0 失败、0 跳过。
- 修改前，以 4,096 条历史复现 function/custom 工具续传无法建立检查点；修改后覆盖连续增量、连接失效后全量恢复、压缩换窗、历史变更拒绝增量及容量边界。
- 真实上游验收使用 Codex CLI 0.166.0-alpha.5.1、gpt-6.1-sol / low。隔离网关向每轮原生请求插入相同的 4,096 条合成消息及一张合成图片：首轮 4,104 项、536,405 字节；后两轮均成功增量，只发送一项新增工具结果，分别为 2,241 / 2,243 字节，历史图片未重发。

真实上游结果来自合成长历史验收，不代表客户端自然积累了 4,096 项历史，也不保证所有线上请求都满足增量条件。此前 9 次未完成请求只能确认下游取消，未发现增量被上游拒绝的证据，不把它们列为已修复故障。

详见 [HTTP/WS 自动增量说明](HTTP_WS_INCREMENTAL.md)。

## 发布产物

仅提供 Linux amd64 二进制包，内嵌从本次提交重新构建的前端，并附构建信息和 SHA256 校验文件。不构建容器或其他平台。
