# GN2API v0.2.54

修正 v0.2.53 新增耗时记录的采集范围。线上核验发现，共用 HTTP 传输的兼容接口和账号用量查询没有接入 Responses 事件观察器，却被记录成 `incomplete`；并行用量查询还可能被误记成重试。此问题属于诊断记录，未修改实际转发行为。

- 仅在具备事件观察器的 Responses HTTP/SSE、HTTP 透传和 WS→HTTP 回退链路创建 HTTP 耗时尝试；HTTP 401 刷新保留同一关联记录。
- 未接入观察器的兼容/辅助调用继续使用既有日志，不再产生假异常或假重试。原生 WS 和 HTTP→WS 的耗时记录保持有效。
- 保留 v0.2.53 的响应 ID 关联、首次内容与实际写出时间、连接复用和增量信息；摘要仍最多 50 MiB、最多保留 7 天，不保存请求或回答正文。
- 前端源码、页面、`visible` 首字统计和转发策略均不变。

已针对未观察调用、编码请求、401 刷新、耗时采集、WS→HTTP 回退以及摘要存储执行回归检查；以随包 `build-info.json` 中的验证结果为准。未将本地测试描述为真实上游验收。

仅提供 Linux amd64 二进制包，内嵌前端资源，附构建信息和 SHA256 校验文件。字段与范围说明见 [请求耗时证据](../deploy/request-timing-evidence.md)。
