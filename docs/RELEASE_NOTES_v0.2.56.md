# GN2API v0.2.56

Chat Completions → Responses 的流式转换原先在第一条上游 SSE 数据到达时就记录首字，状态事件甚至无效 JSON 都可能提前触发。现在遵守全局 `visible` / `semantic` 设置，接入共用事件观察器，并分别记录首事件、首段可见内容、首正文、转换内容实际写出及 Flush 返回时间。快速请求也在原有完成日志中保留这些精简时间点；不改写历史数字，不将 Flush 当作客户端渲染时间。

WS 连接池清理空闲连接时原先按总连接数扣减额度，可能因另一个线程正在工作而额外淘汰本线程的健康空闲连接。现在只按可清理的空闲连接计数，保留已有硬容量限制、健康检查和寿命轮换。增加连接选择/淘汰、绑定未命中、线程用途分类及检查点状态元数据，便于区分正常首次发送、并发、换连接和续传失效。该缺陷已由受控回归用例复现，不把历史全部未增量请求归因为这一处问题。

- Chat Completions 仍走 HTTP/SSE，本次没有新增 WS 接入。
- 增量仍须通过原有线程/租户隔离、参数、历史前缀和工具调用检查；压缩边界或历史变化仍完整发送，已输出的失败请求不静默重放。
- 不降低推理档位、不截断上下文、不更改模型；新增记录仅含时间、计数、固定原因与作用域摘要，不保存真实请求或回答正文。

验证：3,363 项测试及子用例通过，0 失败；1 项独立数据库集成测试因未配置专用测试库跳过。使用受控 HTTP/WS 上游和本地回归测试，覆盖 Chat 首字模式、无内容/错误写出、线程并发下复用、压缩/历史变化回退、完整工具续传及日志隐私。详细测试结果随构建信息发布，不将本地测试描述为生产性能验收。

仅发布 Linux amd64 二进制包，包含新构建的内嵌前端、构建信息和 SHA256 校验文件。计时字段见 [请求耗时证据](../deploy/request-timing-evidence.md)。
