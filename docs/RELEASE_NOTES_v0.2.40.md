# GN2API v0.2.40

修复原生 Codex 历史中的旧推理 ID 在无状态请求中被再次查询，以及 WS 原始错误被通用 `502 / Upstream request failed` 覆盖的问题。

- Codex OAuth 的 HTTP 和 WS 输入均清理 reasoning 条目的旧 `id/call_id`，保留有效密文、摘要、原生元数据和工具调用关联。仅移除已由同一输入中的完整推理条目提供的重复引用；无法还原的其他引用不被静默删除。
- 清理已失效密文时，同时清理该 reasoning 条目的旧标识，避免后续会话再次发送无效查找。正常密文与已有单次恢复重试限制保持原状。
- HTTP 入口收到上游 WS 错误时，保留原始错误类型、代码、参数位置和说明；流式响应使用一个 `response.failed` 终止事件，并记录对应错误状态。Handler 不再追加通用 502。失败仍计入统计，不通过忽略错误提高成功率。

## 验证

- Go 1.27.3 下，service、handler、repository、codexwire 的相关定向回归及修正后的复验，去重合计 1,856 项测试及子用例通过。3 项 scoped-admin PostgreSQL 测试因缺少专用 DSN 跳过，未计入通过。
- 新增/修正覆盖原生 HTTP、透传 HTTP、HTTP→WS、HTTP 回退工具续传、WS 失效密文下一轮，以及流式/非流式错误与 Handler 防重复补写。模型、xhigh、有效上下文、数值精度和工具 call_id 均有断言。
- 首轮新增回归复现旧 ID 与 WS 错误补写问题；修复后发现两处旧测试仍要求保留失效 ID，已纠正。新增回退夹具最初遗漏 HTTP 入站传输标记，补齐后相关场景通过。首次新增测试另有 GetOpsStreamError 返回值接收错误，已在运行回归前修正。
- `gofmt` 与 `git diff --check` 通过。未执行全量后端测试、全量 race 或真实付费模型请求；模拟上游的链路验证不等于模型能力验收。

## 升级

仅更新主程序，需要短暂重启 sub2api。ModelTrace 扩展仍为 `20261102-settings-1`，无需重新安装；没有数据库迁移，不清理历史记录，不修改账号、代理、时区或测试设置。发布包继续包含前端，部署核对 Release、版本、提交和二进制 SHA-256。

已经无法还原的历史内容不会被凭空恢复，个别旧会话仍可能需要重建。升级不会改写之前的错误记录，历史统计按原时间窗口保留。回滚可恢复升级前备份的 v0.2.39 主程序。
