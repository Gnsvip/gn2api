# Sub2API 0.2.20.9

修复历史恢复后的自动压缩遇到临时错误直接结束，以及压缩过程中账号失效或限流后无法携带完整历史继续的问题。

- 自动压缩遇到上游 429、401 或确定的账号凭证失效时，切换其他可用账号，并使用已验证恢复的完整历史重新压缩。429 不在原账号等待重试；跨账号不复用失败账号生成的半成品摘要。
- 临时 5xx、连接重置和响应中断时，在同账号退避后继续失败的分段，保留已经完成的压缩结果。退避逐步增加至 30 秒；上游要求更长冷却时间时遵守该时间。
- 移除压缩专用的 2 分钟总时限、8 次调用上限及三次临时重试上限。调用次数仅用于观测；请求取消或自身超时、余额不足、确定不可恢复的错误仍停止处理。
- 支持 Codex V2 压缩窗口保留的原用户消息有序子序列，严格校验内容及工具关系，并保留新注入的 system/developer 指令。
- HTTP、WS 继续保留当前轮上下文和工具续传关系。内部维护不向客户端泄漏事件，不改变首字计时，不重复准入；已产生的用量按原有规则结算。

验证：183 项相关后端测试通过（含子用例、本地模拟 HTTP/WS 上游、429/401 切号及工具续传、连续临时错误、超过八次分段压缩、取消与计费检查）。Linux amd64 编译通过。全量后端测试未重新执行；这不代表全部线上故障样本均已验收。

仅提供 Linux amd64 二进制，包含嵌入式前端。运行包按白名单生成，不含测试、夹具、缓存或验证脚本。
