# GN2API v0.2.70

修复站内余额不足时，客户端反复提交 HTTP / WebSocket 请求造成重复日志、大正文上传和连接占用的问题；同时发布题目多选界面与性能异常停止调度功能。

- 欠费 HTTP 在读取正文前拒绝。普通请求仍返回 `403 insufficient_quota`；Codex 流式请求保留 `response.failed / insufficient_quota`，不改为上游 429。
- 同一欠费用户共享有限的 WS 失败通知握手预算，连接同时受时间和读取字节上限保护。重复余额拒绝聚合计数，不逐条保存完整错误。充值后沿用认证缓存失效机制恢复使用，不停用用户或 Key。
- 提供 Nginx 入口防护及部署说明：关闭请求正文预缓冲，限制请求到达和连接数，保留正常 SSE / WS 长响应。CDN 部署须配置可信代理真实 IP。应用与入口配置需配套更新。
- 测试题改为下拉多选，最多选择 5 题，每题每轮一次；收起大块题目编辑区，保留按需编辑和独立归因页面。
- 已启用的性能异常保护命中后停止调度，需手动恢复；不会自动启用保护，也不追溯改变旧临时冷却状态。

验证覆盖欠费 HTTP/WS、并发预算、充值恢复、日志聚合与正常上游状态透传。官方 Codex CLI 0.166.0 隔离验收覆盖 HTTP/WS、小输入及约 1.5 MB 输入，每种两轮并观察 140 秒；未出现额外重试。入口突发防护仅在隔离环境压测。远端外层程序仍可能主动提交新请求，本次防护限制服务端处理成本，不承诺控制远端程序。

本次仅提供 Linux amd64 二进制，含所需前端、扩展及校验文件。

部署与回滚说明：[欠费重复请求防护](../deploy/balance-denial-ingress.md)、[性能观察与停止调度](../deploy/traffic-first-token-observation.md)。
