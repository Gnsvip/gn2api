# GN2API v0.2.47

修复 WS 工具输出及后续轮次的首字统计漏记，并修复原生工具历史中空元数据引起的自动增量误判。

## 变更

- HTTP→WS、原生 WS、WS→HTTP 回退及 passthrough 共用首字判定，遵循现有 semantic / visible 设置，补齐工具参数完成、工具条目完成等输出事件。计时与缓冲及重试策略独立。
- 同一 WS 连接第二轮及以后的输出事件省略 `response_id` 时，按活跃轮次独立记录首字，不再受首轮计时状态影响。
- 错误或结束事件不单独作为首字；没有独立可观测输出时保留空值，不用总耗时填充。
- 工具历史比较将 `internal_chat_message_metadata_passthrough` 的 `null`、空对象和省略统一处理；其中 `cell_id`、`executed_tool_calls`、`tool_calls_complete` 仅将 `null` 视为省略，避免误判 `prefix_mismatch`。
- 工具名称、参数、调用 ID、密文、非空执行元数据及未知字段仍严格比较；真实历史变化继续全量回放。比较规范化不修改请求/响应正文，不增加正文持久化记录。

## 验证

- 官方 Codex 0.166.0-alpha.5.1 app-server 对受控工具响应的实测确认：上游空元数据在客户端回放时被省略。
- 实际 Forward 入口覆盖 function/custom tool 的 4 组空元数据续传，修复前失败、修复后仅发送新增工具结果，保留模型、xhigh 和调用关联。
- 相关回归共 240 个不同的顶层测试通过，覆盖 HTTP/WS 转发、工具续传、首字统计、会话生命周期及回退。
- 修改后的隔离网关连接真实上游，原生客户端使用 gpt-6.1-sol / medium，图片输入后的两次工具续传均在同一连接命中增量。两轮完整入站分别为 74,085 / 75,031 字节，实际 WS 出站均为 2,248 字节，没有重复发送历史图片。
- 上述三轮首字分别为 563 / 204 / 192 ms，总耗时为 2,956 / 2,951 / 2,754 ms；这是验收样本，不是延迟保证。

历史未命中样本缺少字段级证据，不能据此认定本次修复覆盖全部历史差异。统计修复不保证上游推理耗时下降，也不保证所有请求命中增量。
