# v0.2.20 对照整合与恢复修复

本次对象是 GN2API 本地待发布工作区，保留此前未提交修复。参考固定为 Wei-Shaw/sub2api 的 `v0.2.20`（`dab829a4e`），三方比较基点为 `d851a38477597157e78450d30af2d8504764d085`。没有发布、部署或修改线上配置。

## 三项恢复修复

1. **WS 透传父响应失效**：识别 `error` 与 `response.failed` 中的 `previous_response_not_found`；只有开关允许、当前轮尚未向客户端提交输出且父历史完整时，才清除旧父 ID，携带完整历史重试。重试移除父 ID，因此重复错误不会进入无限恢复。取消、会话编辑、未知父历史和普通 400 不触发此重放，也不因此处罚账号。
2. **跨账号旧分支**：完成响应的历史容器绑定到当前下游连接，随账号/转发路径尝试存续，保留既有字节预算及最多 32 个快照的上限。换连接后旧父 ID 被标记失效，按对应分支恢复完整输入；旧 turn-state、连接偏好、工具转换状态不移交。客户端间不共享历史，不写入磁盘。
3. **压缩恢复后超大请求**：恢复展开后重新检查实际请求大小，达到既有 HTTP 桥接阈值则用 HTTP 继续当前轮。保留下游 WS、原始计时起点、轮次和计费钩子，避免重复准入；恢复成功后仍可继续下一轮。

## 冲突处理

三方比较检测到 14 个文本冲突文件，其中日文 README 属于品牌/宣传内容，保持本地版本；其余逐处适配。不是直接替换整个网关文件。

- **首字规则**：保留 HTTP semantic、WS semantic 和账号单独覆盖规则；保留已有逐轮计时，不使用上游的较窄事件判定替换它。
- **恢复与计费**：保留之前的压缩恢复、取消保护、上下文完整性、余额预约及换号逻辑。
- **工具流**：将新增的 SSE 配置参数与原有延迟证据记录同时传递，更新相应测试调用。
- **Codex 身份**：保留本地稳定版本模板、TLS 传输与出口身份适配；新增模型描述不等于切换客户端协议基准。
- **HTTP 桥接会话指纹**：上游新增桥接指纹暂存，但其测试要求旧 `session_id` 请求头和账号共用会话，与本地行为冲突。适配后继续使用 `session-id`，设备标识保留在请求元数据中，不额外发送 `x-codex-installation-id` HTTP 头；full 模式保留不同客户端会话隔离。按当前轮账号改写前的正文解析原始会话，避免只有正文携带会话的客户端在 WS→HTTP 边界被重复派生身份。桥接前后的头与正文使用同一份结果。
- **服务生命周期**：保留优雅停机与 Codex transport 清理，加入上游新增缓存/后台任务的关闭钩子。
- **广告与发布**：不合入 README、赞助资产和上游版本号；不改变 Linux amd64 二进制发布偏好。
- **超时语义**：新增写超时按单次 Write/Flush 设置并清除，正常上游思考间隔不占该写超时，不将模型测试的 720 秒预算替换为 120 秒。
