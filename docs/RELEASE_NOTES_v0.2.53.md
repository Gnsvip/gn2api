# GN2API v0.2.53

新增请求耗时摘要，便于通过 `resp_...`、网关请求 ID 和客户端 ID 定位首字较慢的原因。记录时间、类型、计数和大小，不保存正文、图片、工具结果、请求头、凭据或密文。

## 变更

- HTTP 完成日志直接关联 Responses ID；原生 WS 按轮次关联，长连接的中间请求也可以查找。
- 区分连接获取、请求发送、上游首事件、首次可用内容、首次正文、实际下游写出和刷新返回时间。正文、推理内容、工具输入和图片分别分类；额度通知不算内容首字。
- 慢请求（首次内容等待至少 10 秒）、错误和重试额外保存一条耗时摘要，正常快速请求不增加摘要记录。同轮重试保留各次尝试，最多保留第一次与最近七次明细，并注明省略数量。
- 记录连接复用、连接年龄、自动增量原因、可观测的出站大小及事件间隔。原生请求携带续传锚点单独标记，不据此冒充网关自动增量命中。
- 摘要位于应用日志目录的 `request-timing/`，文件内容合计上限 50 MiB、最多保留 7 天，按段自动淘汰；不另行复制到日志数据库。记录失败不会中断用户请求。
- 覆盖普通/透传 HTTP SSE、HTTP 转 WS、原生 WS 连接池、WS 透传和 WS 转 HTTP。未观察到的时间点留空，不填成 0。

本次不修改前端源码、页面、首字统计模式、转发或增量策略。服务端刷新返回时间不等于客户端收到或显示时间，也不能单独证明上游内部是在排队还是推理。

## 验证

- 本地 723 个相关顶层测试通过，含子用例共 1585 项；服务端入口编译检查通过。
- 覆盖关联 ID、逐轮记录、重试保留、内容分类、缓冲写出、存储上限、过期清理、重启读取及现有 HTTP/WS 转发回归。
- Windows 环境未运行 race detector；不将本地合成测试描述为真实上游验收。

仅提供 Linux amd64 二进制包，内嵌同一提交构建的前端，附构建信息和 SHA256 校验文件。

字段说明与查询方法见 [请求耗时证据](../deploy/request-timing-evidence.md)。
