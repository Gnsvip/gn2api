# Sub2API 0.2.20.8

修复压缩摘要失效后，恢复副本在重连时无法匹配、连续压缩依赖旧副本，以及恢复后超限重复失败的问题。

- 会话连接标识变化后，可按认证 Key、分组、线程、执行通道和摘要指纹匹配已有副本；仍校验完整压缩窗口，不猜测其他会话的历史。旧格式副本继续支持原作用域恢复。
- 保存新压缩副本时，将可验证的祖先历史展开到备份内部。淘汰旧副本后，新副本仍可恢复已保留的原始消息、图片和工具关系；正常出站压缩窗口不变。
- 已恢复历史遇到上游上下文超限时，记录对应账号和请求条件；下一次明确请求自动重新压缩后继续生成及工具续传。原来走 WS 的生成继续走 WS，不因该 400 更换账号。
- 保留事件立即转发规则。已发出响应不暗中重放，不重复准入或结算；维护耗时仍计入请求时间。内部压缩遵守准入、取消、额度和调用次数限制。
- 延续 0.2.20.7 的有界、加密、可跨正常重启保留的恢复副本；不保存每一轮请求正文。真正没有有效副本的旧会话仍需要客户端原始历史，无法由失效密文凭空还原。

验证：320 项相关后端测试通过（含子测试、本地模拟上游的 HTTP/WS 端到端场景、同连接与重连续传、持久化恢复和隔离校验）；Linux amd64 编译通过。这不代表线上所有旧会话已经恢复。全量后端测试未重新执行；既有首事件计时测试存在与已发布立即转发行为不一致的断言，未将其标记为通过。

本版不修改前端行为或首字规则。仅提供 Linux amd64 二进制，包含嵌入式前端；运行包按白名单生成，不含测试、夹具、缓存或验证脚本。
