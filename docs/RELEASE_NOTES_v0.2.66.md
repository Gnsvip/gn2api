# GN2API v0.2.66

恢复站内用户余额不足的 **HTTP 403**，纠正 v0.2.64/v0.2.65 将其改为 429 的行为。该拒绝发生在选择上游账号之前，不进入上游重试或切号。

- Responses HTTP、WS 握手及已连接 WS 的站内余额拒绝恢复 403，保留明确的余额不足正文与 `x-should-retry: false`。
- 已开始的 SSE 继续发送 `response.failed`，内部错误归属为余额拒绝，预期状态记为 403。
- 有余额时的上游重试、账号切换、真正上游 429、固定 Key 配额和时间窗限流保持原规则。
- 首字计时、前端、账号调度、余额准入、在途预留和结算不作其他调整。

## 验证与明确限制

- 64 项后端测试及子测试通过，覆盖 403 余额拦截、官方 SDK、HTTP/WS 上游切换及真正限流对照。
- 官方 Node/Python SDK 使用默认重试设置，403 余额拒绝下两次主动调用只产生两次请求；真正限流仍保留重试。
- **原生 Codex“只提示一次”验收仍未通过。**官方 Linux Codex 0.166.0 在收到带禁止重试标记的 403 后，单次 HTTP 调用仍会重连 5 次；WS 还会回退 HTTP。真实 Go 入口配合本机 Codex 的对应测试也保留失败信号，未放宽断言。
- 本版只恢复明确要求的站内余额 403 契约，不能声称已消除所有客户端重连或第三方重复请求。

仅发布 Linux amd64 二进制，内嵌同一提交构建的前端，附 SHA256 校验和构建信息。详见[余额拒绝处理说明](../deploy/balance-denial-repair.md)。
