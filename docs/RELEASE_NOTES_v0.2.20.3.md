# Sub2API 0.2.20.3

修复旧压缩摘要被失效缓存持续拦截的问题，并补齐原生 WebSocket 续接遭拒后的同账号完整上下文恢复。

- **同账号 WS 恢复**：ctx_pool 和 passthrough 均识别 `unsupported_persisted_item_context` 的两种错误事件；仅在尚未输出且持有完整可重放历史时，取消旧响应 ID，用原账号的新 WS 重放完整上下文。保留摘要、图片、工具调用及结果，不因这类上下文 400 换账号或改走 HTTP。
- **失效缓存不再持续误拦**：已知失效的压缩摘要优先使用经过校验的压缩前副本恢复；没有副本时保留原窗口，交同账号、原传输路径的上游重新验证，不因本地拦截不断延长失效标记。
- **保留恢复边界**：摘要解密失败不会通过删除摘要继续生成。已有的历史恢复、恢复后超限重新压缩、输出后禁止重放、取消与重试上限继续生效。
- **凭证失败处理保持有效**：401 的凭证更新、OAuth 刷新及失败后切换可用账号逻辑保留；当前轮上下文必须具备安全重放条件。

## 验证与产物

- 707 项相关测试通过（含父测试和子用例），普通模式服务包编译通过。
- 发布前补跑凭证失效、OAuth 恢复及 WS 切换到 HTTP 备用账号的相关测试，两包全部通过。
- 本地 WS 联调覆盖 ctx_pool / passthrough 和 error / response.failed，确认同账号新建 WS、完整历史恢复、HTTP 调用为零，且不重复准入及计费回调。
- 回归用例补充于已有测试文件，没有新增测试文件；部署包排除测试、夹具、缓存及验证脚本。
- 仅发布 Linux amd64 二进制及必要运行文件，前端复用源码一致且逐文件校验的既有构建。无容器或其他平台产物，无数据库迁移。
- 全局 semantic 首字计时、账号 #12140 的 first_event 配置及前端界面未修改。

## 边界

如果旧摘要已被上游拒绝且没有可用的压缩前历史副本，无法凭空恢复其中的上下文。本次本地验证不代表所有线上旧会话已经恢复。
