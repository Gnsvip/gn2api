# GN2API v0.2.46

修复原生 Codex 通过 HTTP 发送完整历史时，网关无法自动转换为 WS 增量工具续传的问题，并补齐原生 HTTP 消息 ID 校验。

## 变更

- Codex 在下一轮回放中省略上游输出的 `metadata.turn_id` 和 `internal_chat_message_metadata_passthrough.content_token_count`，此前会被误判为 `prefix_mismatch`。历史摘要现在忽略这两个输出附加字段及因此变空的容器，实际请求和响应正文保持原样。
- 未知元数据、正文、密文、工具参数和调用关联仍参与校验；同连接归属、完整工具结果及 10 分钟检查点有效期等限制保持有效。
- 原生 OAuth HTTP 请求继续检查消息 ID，移除错误前缀或超长的消息 ID，兼容省略 `type` 的消息。原生工具 ID 和调用配对保持不变。

## 验证

- 相关回归共 48 个顶层测试、含子用例 202 项通过，0 失败、0 跳过。
- 原生 Codex CLI 0.166.0-alpha.5.1、gpt-6-astra / xhigh，经隔离网关连接真实上游：单次工具续传成功转换为 WS 增量；图片输入后的连续两次工具续传均在同一 WS 连接完成。
- 图片场景中，客户端两次完整 HTTP 请求分别为 73,659 / 74,521 字节，网关对应 WS 增量 JSON 为 2,127 / 2,129 字节，两次均未重复发送历史图片。这些为未压缩 JSON 大小。
- 首轮、连接失效、真正修改历史或无法确认工具关系等情况仍可能使用全量回放；不保证所有请求都命中增量。

## 发布产物

仅提供 Linux amd64 二进制包，内含经校验、源码未变的前端资源；附构建信息和 SHA256 校验文件。本次不构建其他平台或容器镜像。
