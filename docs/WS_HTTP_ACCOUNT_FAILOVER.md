# 原生 WS 换号与 HTTP 备用线路

客户端连接仍为 `WS → sub2`。当前 `ctx_pool` 上游在未输出本轮内容时遇到可换号错误，可由现有调度循环切换为另一 WS 账号或明确启用 `http_bridge` 的 HTTP 账号。HTTP 的 SSE 事件转换成原客户端连接上的 WS 事件。不会要求客户端改用 HTTP，也不会因单次错误永久修改账号传输模式。

## 备用账号配置

- 全局需启用 `gateway.openai_ws.mode_router_v2_enabled`。
- HTTP API Key 账号设置 `extra.openai_apikey_responses_websockets_v2_mode = "http_bridge"`；OAuth 对应 `openai_oauth_responses_websockets_v2_mode`。
- `off` 保持禁用原生 WS 入口选号的含义，不被自动改成桥接。
- 备用号必须能处理 `/v1/responses`。已探测为仅支持 Chat Completions 的上游排除；未探测账号仍沿用现有能力判断，启用前需实测 Responses。
- 分组、模型、额度、账号状态、并发、调度优先级和换号次数限制仍有效。`http_bridge` 本身不是“只作备用”的优先级；需要沿用账号调度配置指定主备顺序。
- `http_bridge_enabled` 与大小阈值负责超大请求的传输回退，不能替代账号的 `http_bridge` 模式配置。

## 上下文边界

换号时重放失败的当前轮：完整输入历史、已完成的助手输出、配对的工具调用和当前工具结果。保留当前轮模型、推理档位、指令和工具声明；按当前模型重新选号并重新应用目标账号的模型映射与身份处理。移除旧账号的 `previous_response_id`，以完整请求在新账号建立会话链。新账号返回后，后续轮次继续使用新链路。

完整性依据为本连接观察到的输入、输出及响应链。只有工具 `call_id` 能配对，不足以证明普通对话历史完整。首帧只有未知旧响应 ID、响应链不匹配、助手输出缺失、包含旧账号的 `item_reference`，或上轮输出未确认完整时，禁止静默删掉锚点后换号；明确要求客户端携带完整历史重新发起请求。

HTTP 桥接续传也保留普通助手回答，使用输出索引和终态事件校验顺序、缺项及冲突。已经输出本轮内容的失败继续遵守现有禁止重放规则，避免重复回答或工具执行。会话历史沿用现有内存回放结构，不新增正文日志、数据库或磁盘记录。

本次后续轮次自动换号针对 `ctx_pool` 与 `http_bridge`。独立 `passthrough` 模式的后续轮次仍走其原有重连策略；不能将这里的结果当作该模式全部场景也已通过。

## 验证与上线

本地受控上游覆盖原生 WS 的首轮凭据拒绝、后续轮次限流、连接轮换后真实握手 401、切换 HTTP 备用及再继续一轮。核对原问题、助手输出、工具关系、当前轮模型切换、`xhigh` 和指令；另测未知锚点、缺失输出、错误响应 ID、显式关闭的账号及仅支持 Chat 的上游。

2026-11-04 本地验证结果：

- `go test -json -tags unit ./internal/service ./internal/handler -count=1 -timeout 8m`：19,736 项测试及子用例通过，12 项按既有条件跳过，0 失败。
- 完整回归后补充旧账号 `item_reference` 保护，相关 service/handler 定向回归 37 项通过，0 跳过、0 失败。
- 原有 401 断言改为验证交给 handler 换号、未写下游且未泄漏上游头；首字用例固定 visible 并恢复全局缓存；连接隔离用例关闭额外利用率预热。三组独立复测三次，共 27 项通过。以上验证在新增 first_event 口径前完成；该口径另有跨传输路径与重试保护回归，连接池预热策略未修改。
- 恢复用例补齐成功终态里的助手输出，断言重放包含该输出；原先缺失历史却允许删锚点的假设不再沿用。

部署时需要同时配置经过验收的 HTTP 备用账号，并通过公开域名验证实际传输路径、工具续传与最终 `response.completed`。不能把普通成功请求视为已触发 401 换号，也不能据此保证所有上游故障均可无缝恢复。
