# 原生 WS 换号与 HTTP 备用线路

客户端连接仍为 `WS → sub2`。`ctx_pool` 以及 v0.2.62 起的 `passthrough` 上游，在本轮尚未尝试写出任何下游事件、且完整历史可以重建时遇到可换号错误，可由现有调度循环切换为另一 WS 账号或明确启用 `http_bridge` 的 HTTP 账号。HTTP 的 SSE 事件转换成原客户端连接上的 WS 事件。不会要求客户端改用 HTTP，也不会因单次错误永久修改账号传输模式。

## 备用账号配置

- 全局需启用 `gateway.openai_ws.mode_router_v2_enabled`。
- HTTP API Key 账号设置 `extra.openai_apikey_responses_websockets_v2_mode = "http_bridge"`；OAuth 对应 `openai_oauth_responses_websockets_v2_mode`。
- `off` 保持禁用原生 WS 入口选号的含义，不被自动改成桥接。
- 备用号必须能处理 `/v1/responses`。已探测为仅支持 Chat Completions 的上游排除；未探测账号仍沿用现有能力判断，启用前需实测 Responses。
- 分组、模型、额度、账号状态、并发、调度优先级和换号次数限制仍有效。`http_bridge` 本身不是“只作备用”的优先级；需要沿用账号调度配置指定主备顺序。
- `http_bridge_enabled` 与大小阈值负责超大请求的传输回退，不能替代账号的 `http_bridge` 模式配置。

## 上下文边界

换号时重放失败的当前轮：完整输入历史、已完成的助手输出、配对的工具调用和当前工具结果。保留当前轮模型、推理档位、指令和工具声明；按当前模型重新选号并重新应用目标账号的模型映射与身份处理。移除旧账号的 `previous_response_id`，以完整请求在新账号建立会话链。新账号返回后，后续轮次继续使用新链路。

完整性依据为本连接观察到的输入、输出及响应链。只有工具 `call_id` 能配对，不足以证明普通对话历史完整。首帧只有未知旧响应 ID、响应链不匹配、助手输出缺失、包含旧账号的 `item_reference`，或上轮输出未确认完整时，禁止静默删掉锚点后换号；明确要求客户端携带完整历史重新发起请求。

HTTP 桥接续传也保留普通助手回答，使用输出索引和终态事件校验顺序、缺项及冲突。已经尝试写出任何本轮事件（包括开始通知）的失败遵守禁止重放规则，避免重复回答或工具执行。会话历史沿用现有内存回放结构，不新增正文日志、数据库或磁盘记录。

`passthrough` 在当前连接内保存有界恢复历史，使用完整输出与索引校验确认上下文。v0.2.20.6 起不再暂存空前置事件；开始通知、推理、正文、工具参数和错误逐事件按序交付。任何下游写入尝试后均禁止本轮透明重放，写入报错也按可能部分送达处理。恢复历史超过入站请求大小上限、出现不能迁移的会话控制操作或无法验证完整历史时，不强行恢复。普通超时及未明确归类为可恢复的错误保留原有关闭/错误处理，并非所有故障都会无缝切号。

底层客户端读取归属当前连接；上游尝试退出时只交接等待者，不丢掉已经读到的下一帧。切号后再次建立上游链路仍需完整请求，后续满足条件才可继续增量。失败轮次的模型归属和余额预留在切号前后保持一致。

## 验证与上线

本地受控上游覆盖原生 WS 的首轮凭据拒绝、后续轮次限流、连接轮换后真实握手 401、切换 HTTP 备用及再继续一轮。核对原问题、助手输出、工具关系、当前轮模型切换、`xhigh` 和指令；另测未知锚点、缺失输出、错误响应 ID、显式关闭的账号及仅支持 Chat 的上游。

2026-11-04 本地验证结果：

- `go test -json -tags unit ./internal/service ./internal/handler -count=1 -timeout 8m`：19,736 项测试及子用例通过，12 项按既有条件跳过，0 失败。
- 完整回归后补充旧账号 `item_reference` 保护，相关 service/handler 定向回归 37 项通过，0 跳过、0 失败。
- 原有 401 断言改为验证交给 handler 换号、未写下游且未泄漏上游头；首字用例固定 visible 并恢复全局缓存；连接隔离用例关闭额外利用率预热。三组独立复测三次，共 27 项通过。以上验证在新增 first_event 口径前完成；该口径另有跨传输路径与重试保护回归，连接池预热策略未修改。
- 恢复用例补齐成功终态里的助手输出，断言重放包含该输出；原先缺失历史却允许删锚点的假设不再沿用。

部署时需要同时配置经过验收的 HTTP 备用账号，并通过公开域名验证实际传输路径、工具续传与最终 `response.completed`。不能把普通成功请求视为已触发 401 换号，也不能据此保证所有上游故障均可无缝恢复。

2026-11-05 / v0.2.62：新增透明 WS 连续三轮集成验收，覆盖流内 401、429 和 502 后切换 HTTP 备用账号，核对完整 4 条历史及下一轮 6 条历史、`xhigh`、工具关系和模型切换；负面用例确认已交付内容、未知锚点、缺失输出和孤立工具结果不会发送给 HTTP 备用账号。相关回归合计 533 个顶层测试、含子场景 1059 项通过，零失败、零跳过。上述验收使用本地模拟上游，不属于线上 OpenAI 实测。

## 大历史传输优化

客户端入口与账号出口独立选择。`http_bridge` 表示客户端 WS → 网关完整历史重建 → 上游 HTTP，不会把已经使用 HTTP 的客户端自动切换成 WS。网站“使用密钥”提供 Codex WebSocket 配置，适用于支持该协议的 CLI、桌面和 VSCode；保存对应 provider 配置并重启客户端后，在新会话核实入口和增量。首轮仍需上传历史，后续只上传新增项。

2026-11-07 本机 Codex 0.167.0-alpha.3.2 对隔离模拟端点的三轮协议验证：预热不生成，首轮 608,695 字节，后两轮各 2,016 字节、一个新增 input 项。该验证没有调用模型，也不等于远端用户已经启用。相同版本在自定义 provider 下，即使启用 `features.enable_request_compression`，HTTP 样本仍为 identity，不能仅凭开关宣称 HTTP 上传已压缩。

API Key 账号可在创建/编辑页面按账号启用 HTTP 请求体压缩，对应 `extra.openai_http_request_compression = "zstd"`，默认关闭。必须先确认目标上游支持。只处理可重放的 POST Responses JSON 请求：64 KiB 至 64 MiB、压缩至少节省 5% 才发送 zstd。保留原始 JSON 字节、全部历史、图片、模型和推理参数，重试仍使用可重放请求体；不改首字口径，不发送能力探测或隐式重复生成。OAuth Codex 已有的出站压缩保持原样。公共 OpenAI 的 100 倍解压比例限制另行保留。

HTTP 客户端与原生 WS→HTTP 桥接共用上述出站编码，仍为 HTTP 出口。编码前大小与实际传输大小分别记录；不开启正文日志。对不支持 `previous_response_id` 的上游，桥接必须保留完整历史，不可仅把客户端增量转发过去。

#12140 于 2026-11-07 的独立探测接受 gzip/zstd，但返回 400 拒绝 HTTP `previous_response_id`。因此采用完整历史的压缩 HTTP；该记录不构成所有 API Key 上游都支持压缩的承诺。

同日使用修改后的桥接与压缩代码对 #12140 真实上游验收：合成长历史首轮 WS 入口 112,164 字节，工具续传和下一轮分别为 573、514 字节；重建完整历史后，HTTP zstd 出站分别为 2,210、2,526、2,747 字节。三轮均完成，工具调用关系和首轮历史校验内容保留，首事件分别为 4.414、3.040、2.174 秒。此为约 2.2 万输入 token 的测试，不代表原来约 19 万 token 的会话性能。生产服务与账号设置未改。相关后端 226 项、前端 159 项测试和前端类型检查通过。

入口上传时间与上游收到请求后的等待须分别验收。传输压缩不会减少模型 token，也不能保证消除第三方上游排队/推理耗时。既有 HTTP 用户在应用原生 WS 配置前仍会完整上传历史；仅发布服务器版本不能改变已经运行的远端客户端。

## 流式事件及时交付（v0.2.20.6）

HTTP OAuth、HTTP API Key、HTTP 透传、HTTP 转 WS、原生 WS 的 ctx_pool/passthrough 和 WS 转 HTTP 均按顺序收到事件即交付，包括 response.created、response.in_progress、推理进度、正文、工具参数和错误。取消前导通知的多事件暂存与批量刷新等待；HTTP 只保留当前 SSE 事件所需的协议分帧，不等待后续内容。

任何下游事件的写入尝试均提交当前响应，即使写入报错也不能假设客户端完全没收到。此后失败明确结束本轮，不吞掉错误、不自动重放当前生成；HTTP 状态/WS 握手失败等尚未交付事件的分支仍按原有条件处理。仅收到 error 而上游不结束时，错误立即发出，最多再等待 1.2 秒收取权威终态及用量，然后结束失败响应；此时间不延迟错误或内容交付。

客户端下一次明确发起续接时，重连并恢复完整上下文。旧响应 ID 已拒绝时移除失效锚点，以可验证的完整历史建立新响应；独立压缩后保留完整压缩窗口及新增输入，不删除摘要后盲目生成。恢复后按已有传输阈值重新路由，准入和计费每轮只执行一次；历史无法验证完整时明确报错。

首字计时独立于交付判断，保留现有 HTTP/WS semantic 和 #12140 first_event 规则。本地 TCP/WS 验证让上游在每个事件后等待客户端确认，覆盖七条路径和停在 error 的异常上游；确认事件顺序、立即交付和一次上游生成。16 组持续/突发正文与工具传输场景验证内容完整。这些验证不代表线上上游生成速度。

协议依据：[OpenAI WebSocket mode — Reconnect and recover](https://developers.openai.com/api/docs/guides/websocket-mode#reconnect-and-recover)。公共 API 文档不等同于 OAuth Codex 后端的完整协议保证，后者继续按既有基线验证。本文较早版本的空通知暂存、流内错误透明重试验收记录属于历史行为，v0.2.20.6 以本节规则为准。
